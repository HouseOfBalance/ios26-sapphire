# Codex Engineering Context: HakiOS XNU 12377 (iOS 26) on Snapdragon 685 (Bengal)

## 1. System Role & Architecture Context
You are a Principal XNU Kernel & Low-Level ARM64 Systems Engineer working on **HakiOS**.
- **Objective:** Port Apple XNU 12377.121.6 (iOS 26 / Darwin 26.0.0, arm64e) to non-Apple silicon: Qualcomm Snapdragon 685 (SM6225 Bengal) on Xiaomi Redmi Note 13 4G ("sapphire").
- **Target Architecture & CPU:**
  * 4x Kryo 260 Gold (Cortex-A73) + 4x Kryo 260 Silver (Cortex-A53).
  * Architecture Baseline: **ARMv8.0-A only**.
  * Missing Hardware Features (Compared to Apple Silicon / ARMv8.3+):
    - NO Hardware PAC (Pointer Authentication).
    - NO Hardware LSE atomics (`cas`, `swp`, `ldadd` etc.).
    - NO Hardware `FEAT_LRCPC` (`ldapr`, `ldapur`, `stlur`).
    - **MMU Hardware Granule:** Hardware only supports **4KB and 64KB** translation granule (NO 16KB hardware granule!).
    - **Mach VM Software Granule:** XNU 12377 strictly expects a **16KB software granule**.
    - **Solution in place:** 4KB Quad-PTE emulation layer (`0004-pmap-4kb-quad-pte.patch`) mapping four 4KB hardware page table entries per one 16KB Mach VM page.
- **Physical Memory Map:**
  * RAM: Single contiguous 1024 MB window:
    - Base: `gPhysBase = 0x80000000`
    - Size: `mem_size = 0x40000000` (1 GB)
    - Available RAM End: `avail_end = 0xc0000000`
  * Early Framebuffer: 1080x2400 AMOLED display at PA `0x5c000000` (`rowBytes = 4320`, 32-bit ARGB).
- **Boot Chain:**
  1. Primary/Secondary Bootloader: Android Bootloader (ABL) hands off at EL1.
  2. Enxerto Bootloader (`enxerto/loader.c`): Decompresses payload, sets up ADT (Apple Device Tree `sapphire.adt`) and `boot_args` (`virtBase`, `physBase`, `memSize`, `topOfKernelData`).
  3. Mach-O Kernel (`mach.development.bcm2837`): Bootstraps at entry VA.

## 2. Early Diagnostics & Debugging Constraints
- **NO EARLY SERIAL UART CONSOLE:** The hardware UART is multiplexed or disabled by primary firmware during bring-up.
- **Visual Color Ladder:** Early debugging uses direct writes to the physical framebuffer at `0x5c000000`:
  ```c
  extern void hk_draw_band(uint32_t color, uint32_t row_start, uint32_t row_count);
  ```
  * Signature: `color` (ARGB32), `row_start` (display row 0..2399), `row_count` (height in rows).
  * Common colors: White (`0x00FFFFFF`), Red (`0x00FF0000`), Green (`0x0000FF00`), Cyan (`0x0000FFFF`), Yellow (`0x00FFFF00`), Magenta (`0x00FF00FF`), Gold (`0x00FFD700`), Dark Orange (`0x00FF8C00`), Deep Pink (`0x00FF1493`).
- **CRITICAL CONSTRAINT:** Any `panic()` or failed `assert()` prior to console attachment results in an infinite `wfe` loop (silent CPU freeze with no text).
  * **RULE:** Never introduce panicking assertions in early boot code.
  * **RULE:** Use fail-safe clamps, safe defaults, and visual color bands.

## 3. Subsystems Solved & Verified Working (DO NOT REGRESS)
1. **PAC Trap-and-Self-Patch Engine:** Intercepts PAC instructions in `sleh_synchronous` and rewrites them dynamically to NOPs/ARMv8.0 equivalents.
2. **LSE Atomic Branch Islands:** Emulates LSE atomics using LDXR/STXR loop sequences.
3. **Generic ARM Architecture Timer:**
   - Apple system registers (`ACNTVCT_EL0` / `S3_4_C15_C10_6`) replaced with standard ARM `isb; mrs x0, cntvct_el0`.
   - Frequency initialized to 19.2 MHz (Qualcomm Bengal base clock).
   - Divide-by-zero guards in `absolutetime_to_nanoseconds`.
4. **Boot Sequence Progress (Verified on Physical Device):**
   - `kernel_bootstrap` entry (Cyan, row 184)
   - `vm_mem_bootstrap` (Dark Orange, row 240)
   - `vm_page_bootstrap` (Gold, row 244)
   - `vm_page_buckets` (Cyan, row 248)
   - `vm_page_bucket_locks` (Magenta, row 252)
   - `pmap_startup` (Yellow, row 256)
   - `page_frame_init` (Gold, row 260)
   - `pf:t0` (Cyan, row 264)
   - `mach_absolute_time()` (PASSED - generic timer works at EL1)
   - `pf:t1` (Magenta, row 268)
   - `absolutetime_to_nanoseconds()` (PASSED)
   - `pf:t2` (Yellow, row 272)
5. **Fail-Safe `initialize_ram_ranges()` & `pmap_free_pages_span()`:**
   - Normalizes `first_avail` from kernel VA to PA via `ml_static_vtop()`.
   - Clamps invalid RAM boundaries to prevent underflow.
   - Replaced panicking asserts with diagnostic bands (White row 280, Lime row 292, Gold row 294).
6. **Aperture-Based Early Steal:**
   - In `pmap_steal_memory_internal` when `!pmap_initialized`, allocates physical pages using `pmap_next_page(&pn)`, bzeros at `phystokv(pa)`, and bypasses the blocking `pmap_enter` loop.

## 5. Strict Codex Rules of Engagement
1. **Never use Apple Silicon sysregs:** E.g., `S3_4_C15_C10_6`, `ACC_OVRD`, Apple AMX, or AIC registers. All CPU interactions must be compatible with ARMv8.0 Cortex-A73.
2. **Never break 16KB Granule Semantics in Mach VM:** All allocations handed to Mach VM must align to `PAGE_SIZE` (16KB, `PAGE_SHIFT = 14`, `PAGE_MASK = 0x3FFF`).
3. **No Panicking Asserts in Early Init:** If an assertion could fail during early boot before console is online, use a safe clamp, log via `hk_draw_band()`, and continue.
4. **Idempotent Python Patches:** Any patch script in `kernel/` must be idempotent (safe to run multiple times, exiting 0 if `[ALREADY PATCHED]`).
5. **Clean Commits:** NEVER add `Co-Authored-By` trailers in git commits.
